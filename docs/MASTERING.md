# Mastering: research brief and implementation

Mastering turns the raw mix bus (the premaster) into a release: balanced, controlled, loud enough, safe on every playback system. In Spectre it is a separate final stage (`engine/master.py`, run as `studio.py master vNNN`).

## Why it was added
Session 001 ("Bleachers") sounded clunky on MacBook speakers. Analysis showed the 808 fundamental around 50 Hz sitting about 17 dB above the midrange in the long-term spectrum, so most of the track's energy sat where laptop speakers physically can't play, plus inter-sample true peaks around -1.4 dBTP.

## Principles (from the research)
- **Chain order:** corrective EQ, then dynamics (gentle glue; multiband only where needed), then saturation or enhancement, then stereo, then a limiter last. Working mastering engineers use multiband compression much less than tutorials suggest.
- **Loudness:** streaming platforms normalize to about -14 LUFS integrated (Apple about -16). A louder master just gets turned down. Spotify asks for a true peak under -1 dBTP, or under -2 dBTP for masters louder than -14 LUFS.
- **True peak, not sample peak:** reconstruction between samples can exceed 0 dBFS. Measure and limit at 4x oversampling.
- **Mono low end:** keep everything below about 120-200 Hz mono (high-pass the side channel).
- **Small-speaker translation:** laptops and phones can't reproduce sub bass. Harmonics of the bass, generated by saturation, let the brain infer the missing fundamental. Mid-range energy, not sub, is what makes a track read on small speakers.
- **Fix in the mix when you can:** a master that has to make huge corrections is a sign the mix needs work.

## Implementation (`engine/master.py`)
| Stage | What it does |
|---|---|
| 0. Analyse | Integrated LUFS, true peak (4x), 1/3-octave long-term spectrum (gated to the loud parts) |
| 1. Clean-up | 28 Hz 8th-order high-pass; side channel high-passed below 120 Hz (linear phase) so the low end is mono |
| 2. Tonal EQ | Two-pass linear-phase EQ that moves the spectrum toward a hip-hop target curve, aligned on 200 Hz-5 kHz. Strength set by `--eq`; at most -8/+4 dB per band in total |
| 3. Multiband | 4 linear-phase bands (120 / 600 / 4000 Hz crossovers) that sum back perfectly; each compresses only its own loudest peaks (threshold from its 95th percentile) |
| 4. Translation | 55-150 Hz bass body to tanh saturation to a 160-700 Hz band-pass, mixed in (`--translate`) |
| 5. Glue | 2:1, 30 ms attack, 200 ms release, about 1-2 dB of reduction |
| 6. Clip + limit | Soft clipper (4x) into a look-ahead true-peak limiter running 4x oversampled, ceiling `--tp` |
| 7. Loudness | The input drive is solved iteratively so integrated loudness lands on `--lufs` (±0.15 LU) |
| 8. QC | LUFS, true peak, PLR, loudness range, low-end L/R correlation, laptop loss (loudness change after a 180 Hz high-pass), remaining tonal deviations, warnings; before/after picture |

Defaults: `--lufs -11 --tp -1 --eq 0.7 --translate 0.5` (session 001 used `--eq 0.9`).

The target curve is in `TARGET_ANCHORS` (dB relative to 1 kHz per 1/3 octave). It is a hand-tuned modern hip-hop balance, not measured from references. Reference matching is a good next step.
